DUCK HUNT MECHANICS IMPLEMENTATION SPEC FOR CURSOR
Plaintext engineering brief

Scope

Build a deterministic gameplay-mechanics recreation of NES Duck Hunt with these modes only:

1. GAME_A_ONE_DUCK: one duck at a time, single player only.
2. GAME_B_TWO_DUCKS: two ducks per wave, single player only.
3. GAME_C_CLAY_SHOOTING: two clay pigeons per wave, single player only.

Do not implement the hidden second-player duck-control behavior. Ignore controller-based duck steering entirely. This spec is for target behavior, shooting rules, round progression, scoring hooks, timing, and gameplay audio triggers. It does not include original art, title-screen behavior, pause behavior, or top-score persistence. Audio is included as event timing, queue behavior, and NES-style synthesis guidance. Do not embed original Nintendo audio samples unless you have the rights; use licensed samples or synth approximations.

Use a fixed 60 fps gameplay update. Use a 256 x 240 NES virtual coordinate space, then scale to your display resolution. Keep entity positions as integer NES pixels unless a section says fixed point.

Source basis

- Duck Hunt disassembly, Duck-ssembly-Hunt, RussianManSMWC.
- Duck Hunt NES instruction booklet.
- NESdev Zapper behavior notes.
- Empirical flight analysis by GG for sanity checking speed, duration, and hitbox changes.
- Duck Hunt sound queue constants and sound engine behavior from the Duck-ssembly-Hunt disassembly.
- NESdev APU notes for channel architecture and register-level modeling.

Implementation priority

To make the game feel like Duck Hunt, do these exactly:

1. Use a 60 fps fixed-step update.
2. Use motion-code micro-patterns, not smooth random velocities.
3. Use the speed-cycle table to apply 1 to 7 movement substeps per frame.
4. Use scripted paths for GAME_B_TWO_DUCKS.
5. Use launch paths plus boundary-driven random redirection for GAME_A_ONE_DUCK.
6. Use 3 shots per duck or pair.
7. Use 10 targets per round.
8. Use the pass-line table exactly.
9. Shrink the Zapper hitbox by round.
10. For clay pigeons, use the fixed-point projectile update and distance-based hitbox shrink.
11. Trigger audio from gameplay events, not from loose animation guesses. Keep wing flaps, shots, quacks, dog barks/laughs, duck fall, clay throw/fly/hit, round-clear, perfect, and game-over cues synced to the same states that drive the visuals.

------------------------------------------------------------
2. RNG MODEL
------------------------------------------------------------

The original uses a 4-byte shift-register RNG. For gameplay matching, implement this for explicit RNG calls used in path selection, release delay, color selection, and boundary direction changes.

Pseudocode

function rngNext():
    feedback = ((rngState[0] & 0x02) ^ (rngState[1] & 0x02)) != 0
    carry = feedback ? 1 : 0

    for i in 0..3:
        old = rngState[i]
        rngState[i] = ((carry << 7) | (old >> 1)) & 0xFF
        carry = old & 0x01

    return rngState[0]

Seed

If your seed byte is 0, initialize rngState[0] to 0x5F. For a modern deterministic clone, expose a seed option. The original also advances RNG while waiting for NMI, so exact emulator-level RNG timing depends on CPU timing. For a gameplay clone, call rngNext only at the explicit places described below.

------------------------------------------------------------
3. ZAPPER AND HIT DETECTION MODEL
------------------------------------------------------------

Modern input replacement

Use the mouse, pointer, or reticle position as the Zapper aim point. Convert the aim point to NES virtual coordinates.

When the player fires:

1. If shotCount == 0, ignore the shot.
2. Decrement shotCount immediately.
3. Test active shootable targets in target slot order.
4. If a target is hit, set it to its HIT state, increment currentHitCount, increment currentWaveHitCount, and stop testing further targets for that shot.
5. If nothing is hit and shotCount reaches 0, ducks enter fly-away behavior. Clays keep flying until their trajectory ends.

Original CRT behavior

The original flashes white 8 x 8 sprite squares over a target on a black screen. For a modern clone, simulate the union of those white 8 x 8 squares.

Hit test function

function pointHitsZapperShape(pointX, pointY, targetX, targetY, shapeId):
    for each (dy, dx) in ZAPPER_SHAPES[shapeId]:
        rectX = targetX + signed(dx)
        rectY = targetY + signed(dy)
        if pointX >= rectX and pointX < rectX + 8 and
           pointY >= rectY and pointY < rectY + 8:
            return true
    return false

Important: these offset pairs are listed as dy, dx. The first value modifies Y, the second modifies X.

5. DUCK MOTION MICRO-PATTERNS
------------------------------------------------------------

Do not use smooth velocities. Each motion code is a repeating list of tiny signed pixel deltas. Each movement substep consumes one delta pair. If the pattern reaches the terminator, loop to the beginning of that pattern.

Each pair is dy, dx.

Notes

- Codes 0-15 are the normal compass-like duck flight directions.
- Code 16 is used for falling wobble.
- Codes 18-20 are fast upward escape motions.
- Pattern entries of (0,0) are real no-op substeps in some patterns, not terminators. The terminator is only in the original data table. In this high-level representation, just loop the list.

------------------------------------------------------------
6. SPEED CYCLE TABLE
------------------------------------------------------------

A speed index points into a 4-entry cycle. Each frame, read one value from the cycle. That value is the number of motion substeps to apply this frame. Then advance within the 4-entry group. When the index reaches the end of the group, wrap back to the start of that same 4-entry group.

SPEED_CYCLES_BY_INDEX = {
  0x00: [1,1,1,1],
  0x04: [2,1,1,1],
  0x08: [2,1,2,1],
  0x0C: [2,2,2,1],
  0x10: [2,2,2,2],
  0x14: [3,2,3,2],
  0x18: [3,3,3,3],
  0x1C: [4,3,4,3],
  0x20: [4,4,4,4],
  0x24: [5,5,5,5],
  0x28: [6,6,6,6],
  0x2C: [7,7,7,7]
}

Implementation

function readSpeedAndAdvance(entity):
    cycleStart = entity.speedIndex & 0xFC
    cycleOffset = entity.speedIndex & 0x03
    steps = SPEED_TABLE[cycleStart + cycleOffset]
    cycleOffset = (cycleOffset + 1) & 3
    entity.speedIndex = cycleStart + cycleOffset
    return steps

8. GAME A, ONE DUCK, SINGLE PLAYER ONLY
------------------------------------------------------------

Wave structure

- One duck per wave.
- Three shots per duck.
- No second-player duck control.
- The dog presentation can be simplified, but the duck launch timing should still start with releaseDelayFrames = 0x30 after the dog/wave handoff.

Game A duck speed by round

round 1:      speedIndex = 0x10, average 2.00 substeps/frame
rounds 2-3:  speedIndex = 0x14, average 2.50 substeps/frame
rounds 4-5:  speedIndex = 0x18, average 3.00 substeps/frame
rounds 6-7:  speedIndex = 0x1C, average 3.50 substeps/frame
rounds 8-9:  speedIndex = 0x20, average 4.00 substeps/frame
rounds 10-11:speedIndex = 0x24, average 5.00 substeps/frame
rounds 12+:  speedIndex = 0x28, average 6.00 substeps/frame

Game A fly-away timer

The timer starts only after the launch phase ends, meaning after the duck rises above the grass and y < 0x88.

Rounds 1-10:  timer = 0x7D ticks. Decrements every other frame. About 4.17 seconds after launch ends.
Rounds 11-19: timer = 0x5D ticks. Decrements every other frame. About 3.10 seconds after launch ends.
Rounds 20+:   timer = 0x3E ticks. Decrements every other frame. About 2.07 seconds after launch ends.

This is not the full visible lifetime. Full visible lifetime includes launch travel plus escape travel. Empirical sanity target: around 11.5 seconds visible on round 1, falling to about 5.1 seconds by round 20+.

Game A launch paths

Path IDs 0x10-0x1F are used. Each entry is:

[startX, launchSegmentDuration, initialMotionCode]

launchSegmentDuration is always 0xE0 substeps. The launch phase ends early when y < 0x88.

Game A state READY_WAITING_TO_LAUNCH

When releaseDelayFrames reaches zero:

1. Select launch path as above.
2. x = path.startX
3. y = 0xA8
4. motionCode = path.initialMotionCode
5. segmentTimer = path.launchSegmentDuration
6. pathIndex can point after the segment, but it will not matter after launchFlag clears.
7. launchFlag = true
8. flyAwayFlag = false
9. flyAwayTimer = selected by round
10. zapperShape = selected by round
11. speedIndex = selected by round
12. state = FLYING_AND_SHOOTABLE
13. currentTargetCount += 1

Game A active flying update

function updateGameADuck(duck):
    if shotCount == 0 and not duck.flyAwayFlag:
        duck.flyAwayFlag = true
        duck.segmentTimer = 0xF0
        setMotionCode(duck, 0)      // upward

    if duck.launchFlag:
        if duck.y < 0x88:
            duck.launchFlag = false
        else:
            applyScriptedLaunchMotionThisFrame(duck)
            return

    if not duck.flyAwayFlag:
        if frameCounter is odd:
            duck.flyAwayTimer -= 1
            if duck.flyAwayTimer == 0:
                duck.flyAwayFlag = true
                showFlyAwayMessageIfNoDuckHitThisWave()

    if duck.flyAwayFlag:
        updateDuckEscapeBoundaryLogic(duck)
    else:
        updateDuckNormalBoundaryLogic(duck)

    steps = readSpeedAndAdvance(duck)
    repeat steps times:
        applyNextMotionMicroDelta(duck)

    updateDuckAnimationFromMotion(duck)

Normal free-flight bounds

If not in fly-away mode, keep ducks in this box:

y < 0x20:  nudge y += 1 and choose a new downward-safe direction
y >= 0x90: nudge y -= 1 and choose a new upward-safe direction
x < 0x10:  nudge x += 1 and choose a new right-safe direction
x >= 0xF0: nudge x -= 1 and choose a new left-safe direction

After any boundary change, continue moving with the new motion code.

Escape bounds

When flyAwayFlag is true, use escape bounds instead of normal bounds:

if y < 0x08: clear duck
if x < 0x0C: clear duck
if x >= 0xF4: clear duck
if y >= 0x90: nudge upward and choose an upward-safe direction
otherwise continue movement and allow the duck to leave through the top or sides

Boundary direction selection

For a close recreation, implement this instead of simple vector reflection.

function chooseBoundaryMotion(duck, boundaryType):
    // boundaryType can be TOP, BOTTOM, LEFT, RIGHT.
    // This mirrors the original's biased redirection logic.

    if boundaryType == TOP:
        duck.y += 1
        boundaryCode = 0
        sideBase = duck.motionCode & 0x08
    else if boundaryType == BOTTOM:
        duck.y -= 1
        boundaryCode = 2
        sideBase = duck.motionCode & 0x08
    else if boundaryType == LEFT:
        duck.x += 1
        boundaryCode = 4
        sideBase = 0
    else if boundaryType == RIGHT:
        duck.x -= 1
        boundaryCode = 2
        sideBase = 0x08

    base = ((duck.motionCode & 0x07) ^ 0x07) | sideBase
    r = rngNext() & 0x03
    if r == 3: r = 2
    candidate = base + r

    if candidate == 0:
        if boundaryCode == 2: candidate -= 1
        else: candidate += 1
    else if candidate == 4:
        if boundaryCode == 0: candidate += 1
        else if boundaryCode == 2: candidate -= 1
        else: candidate += randomPlusMinusOne()
    else if candidate == 8:
        if boundaryCode == 0: candidate += randomPlusMinusOne()
        else: candidate -= 1
    else if candidate == 12:
        if boundaryCode == 0: candidate -= 1
        else: candidate += 1

    duck.motionCode = candidate & 0x0F

function randomPlusMinusOne():
    // Original uses bit 7 of rngNext after an ASL.
    return ((rngNext() & 0x80) != 0) ? +1 : -1

Hit and fall behavior

When hit:

1. state = HIT_MARK_AND_SCORE.
2. Mark hit table for this target.
3. currentHitCount += 1.
4. currentWaveHitCount += 1.
5. Add score according to color and round.
6. Enter HIT_PAUSE for 0x12 frames.
7. Then enter START_FALLING.
8. In falling, use motion code 16 and fall until y >= 0xB0.
9. Then clear the duck.

- Two duck slots are enabled.
- Three shots are shared by both ducks.
- First duck launches after releaseDelayFrames = 0x30 frames.
- Second duck launches after a random delay of 1 to 64 frames after the first duck initializes.
- The two-duck mode is single player only.

Game B path format

Each path is:

[startX, duration1, motionCode1, duration2, motionCode2, ..., 0xFF, nextState, extra]

Duration is in movement substeps, not frames. Higher speed cycles consume the same path faster because more substeps are applied per frame.

When segmentTimer reaches 0:

1. Read the next byte.
2. If it is 0xFF, set state = nextState and stop.
3. Otherwise, that byte is segmentTimer.
4. Read the following byte as motionCode.
5. Continue movement.

function spawnDuckWave():

    currentWaveHitCount = 0

    select currentDuckConfiguration as described above

    handleShotInputIfAny()

    updateDuck(duckSlot0)
    updateDuck(duckSlot1)

        releaseDelayFrames -= 1

    if pendingDuckLaunches == 0 and no duck slot is active or shootable:

function updateDuck(duck):
    switch duck.state:
        case IDLE_OR_CLEARED:
            return

        case INIT:
            initializeDuckDefaults(duck)
            duck.state = READY_WAITING_TO_LAUNCH
            return

        case READY_WAITING_TO_LAUNCH:
            if releaseDelayFrames > 0: return
            initializeDuckLaunch(duck)
            pendingDuckLaunches -= 1
            releaseDelayFrames = (rngNext() & 0x3F) + 1
            return

        case FLYING_AND_SHOOTABLE:
            if mode == GAME_A_ONE_DUCK:
                updateGameADuck(duck)
            else:
                updateGameBDuck(duck)
            return

        case HIT_MARK_AND_SCORE:
            markHitAndAddScore(duck)
            duck.hitPauseTimer = 0x12
            duck.state = HIT_PAUSE
            return

        case HIT_PAUSE:
            duck.hitPauseTimer -= 1
            if duck.hitPauseTimer == 0:
                duck.state = START_FALLING
            return

        case START_FALLING:
            spawnScorePopup(duck)
            setMotionCode(duck, 16)
            duck.state = FALLING
            return

        case FALLING:
            steps = readSpeedAndAdvance(duck)
            repeat steps times:
                applyNextMotionMicroDelta(duck)
            if duck.y >= 0xB0:
                duck.state = CLEAR
            return

        case CLEAR:
            clearDuckSprites(duck)
            duck.active = false
            duck.state = IDLE_OR_CLEARED
            return

function updateGameBDuck(duck):
    if shotCount == 0 and not duck.flyAwayFlag:
        duck.flyAwayFlag = true
        duck.segmentTimer = 0xF0
        setMotionCode(duck, 0)

    if duck.segmentTimer == 0:
        byte = duck.pathData[duck.pathIndex]
        duck.pathIndex += 1

        if byte == 0xFF:
            duck.state = duck.pathData[duck.pathIndex]
            duck.pathIndex += 1
            duck.extra = duck.pathData[duck.pathIndex]
            return

        duck.segmentTimer = byte
        newMotion = duck.pathData[duck.pathIndex]
        duck.pathIndex += 1
        setMotionCode(duck, newMotion)

    steps = readSpeedAndAdvance(duck)
    repeat steps times:
        if duck.segmentTimer > 0:
            duck.segmentTimer -= 1
        applyNextMotionMicroDelta(duck)

    updateDuckAnimationFromMotion(duck)

11. GAME C, CLAY SHOOTING, SINGLE PLAYER ONLY
------------------------------------------------------------

Wave structure

- Two clay slots are enabled.
- Three shots are shared by both clays.
- At the start of each pair, releaseDelayFrames = 0x80.
- First clay launches when releaseDelayFrames reaches zero.
- Second clay launches after a random delay of 1 to 64 frames after the first clay initializes.
- No dog target behavior is needed for clay mode.

ClayState

0 IDLE_OR_CLEARED
1 INIT
2 READY_WAITING_TO_LAUNCH
3 FLYING_AND_SHOOTABLE
4 HIT_START_FRAGMENTATION
5 FRAGMENTING
8 CLEAR

Clay trajectory model

The original clay pigeon uses three 5-byte fixed-point groups. Treat these as internal projectile values, not screen pixels. The screen x and y are projected from these values each frame.

Use entity memory bytes m[0..14] representing original addresses $40..$4E:

Group A, m[0..4], original $40..$44: horizontal-ish component.
Group B, m[5..9], original $45..$49: distance/depth component.
Group C, m[10..14], original $4A..$4E: vertical-ish component.

Each group layout:

m[base + 0] = acceleration
m[base + 1] = velocity low
m[base + 2] = velocity high
m[base + 3] = position low
m[base + 4] = position high

Clay path table

Each launch path has 6 bytes:

[set_$44, set_$43, set_$4A, set_$42, set_$47, set_$4C]

Clay fixed-point update

Use unsigned 8-bit math. Values wrap at 0xFF. Signed checks use bit 7.

function signByte(b):
    return 0xFF if (b & 0x80) else 0x00

function updateClayFixedPoint(m):
    // Update groups in this order: group C at base 10, group B at base 5, group A at base 0.
    for base in [10, 5, 0]:
        acc = m[base + 0]
        signAcc = signByte(acc)

        // velocity low += acceleration
        sum1 = acc + m[base + 1]
        carry1 = sum1 > 0xFF ? 1 : 0
        m[base + 1] = sum1 & 0xFF

        // velocity high += sign(acceleration) + carry
        sum2 = signAcc + m[base + 2] + carry1
        m[base + 2] = sum2 & 0xFF
        signVelHigh = signByte(m[base + 2])

        // Original doubles velocity low and uses its carry while adding velocity high to position low.
        carryFromVelLowShift = (m[base + 1] & 0x80) ? 1 : 0
        m[base + 1] = (m[base + 1] << 1) & 0xFF

        // position low += velocity high + carryFromVelLowShift
        sum3 = m[base + 2] + m[base + 3] + carryFromVelLowShift
        carry3 = sum3 > 0xFF ? 1 : 0
        m[base + 3] = sum3 & 0xFF

        // position high += sign(velocity high) + carry
        sum4 = signVelHigh + m[base + 4] + carry3
        m[base + 4] = sum4 & 0xFF

Clay projection

For a close clone, port the original projection routine. For a gameplay-feel clone, use this approximation:

z = max(1, clay.m[9])
rawX = ((clay.m[4] << 8) | clay.m[3])
rawY = ((clay.m[14] << 8) | clay.m[13])

screenX = 128 + ((signed16(rawX) * 108) / (z + 32))
screenY = 176 - ((signed16(rawY) * 80) / (z + 32))

Clamp only for rendering. Do not clamp the internal fixed-point trajectory. The original clears the target when m[14] is negative or m[9] >= 0x30.

13. AUDIO MECHANICS AUDIT
------------------------------------------------------------

Goal

Audio is not just polish in this recreation. Several sounds are tied directly to gameplay state changes and animation timing:

- gunshot when the Zapper shot is accepted
- duck wing tick while a duck is flying
- duck quack during flight and hit pause
- duck falling sound when a shot duck starts falling
- ground thud when the fallen duck reaches the grass/ground threshold
- dog bark during the pre-duck dog animation
- dog laugh when all ducks in a duck wave escape
- got-duck jingle when at least one duck in the wave was hit
- clay throw when a clay pigeon launches
- clay flying/falling tone shortly after clay launch
- clay shatter hit noise during fragmentation
- round-clear fanfare, perfect jingle, and game-over cues

NES audio hardware model

The NES APU has five channels:

1. pulse 1 / square 1
2. pulse 2 / square 2
3. triangle
4. noise
5. DMC sample playback

Duck Hunt uses all five categories. Bark and duck quack are DMC samples. Gunshot, wing flap, clay hit, duck fall, clay flying/falling, dog laugh, and fanfares use the programmable APU channels.

For a modern clone, implement one of these two approaches:

Approach A, preferred for feel:

- Create a small NES-style synth layer with pulse1, pulse2, triangle, noise, and sample playback buses.
- Drive it from the same 60 fps gameplay loop.
- Use the event queue model below.

Approach B, acceptable if schedule is tight:

- Use short replacement WAV/OGG assets.
- Still trigger them from the same states and frame timings below.
- Do not trigger by approximate visual observation. Trigger by entity state transitions.

Sound queue model

The original uses three bitfield queues:

Sound_SFX1Queue
Sound_SFX2Queue
Sound_SFX3Queue

A queue function ORs the requested bit into the queue. The sound engine scans and consumes these queues once per gameplay frame.

Queue 1, momentary SFX and active noise/triangle/square effects:

SFX1_SILENCE            = 0b00000001
SFX1_ZAPPER_SHOT        = 0b00000010
SFX1_CLAY_PIGEON_HIT    = 0b00000100
SFX1_WING_FLAP          = 0b00001000
SFX1_DUCK_FALL          = 0b00010000
SFX1_CLAY_FLYING_TONE   = 0b00100000   // called ClayPigeonFall in disassembly
SFX1_DOG_LAUGH          = 0b01000000
SFX1_STOP_SQUARE2       = 0b10000000   // used as a stop/silence helper for clay flying tone

Queue 2, fanfares/themes:

SFX2_CLAY_START_THEME   = 0b00000001
SFX2_TITLE_THEME        = 0b00000010   // optional, outside this gameplay spec
SFX2_GAME_OVER_THEME    = 0b00000100
SFX2_GOT_DUCK_JINGLE    = 0b00001000
SFX2_DUCK_START_THEME   = 0b00010000
SFX2_HIT_TABLE_SHUFFLE  = 0b00100000
SFX2_BEAT_ROUND_THEME   = 0b01000000
SFX2_PAUSE_JINGLE       = 0b10000000   // optional if pause is out of scope

Queue 3, DMC samples and small gameplay jingles:

SFX3_BARK               = 0b00000001
SFX3_QUACK              = 0b00000010
SFX3_UNUSED_BIT_2       = 0b00000100

Audio engine update order

Call updateAudioFrame() once per gameplay frame, after gameplay state has queued sounds for that frame.

The exact original engine scans bits rather than storing a timestamped FIFO. For a modern implementation, this approximation is close:

function updateAudioFrame():
    // DMC sample starts can layer with programmable APU effects.
    if soundSfx3Queue & SFX3_BARK:
        startDmcSample(DMC_BARK)
    else if soundSfx3Queue & SFX3_QUACK:
        startDmcSample(DMC_QUACK)

    if soundSfx1Queue & SFX1_SILENCE:
        silenceProgrammableChannels()

    if soundSfx1Queue & SFX1_ZAPPER_SHOT:
        startZapperShotNoise()

    if soundSfx1Queue & SFX1_CLAY_PIGEON_HIT:
        startClayHitNoise()

    if soundSfx1Queue & SFX1_WING_FLAP:
        startWingFlapNoiseTick()

    if soundSfx1Queue & SFX1_DUCK_FALL:
        startDuckFallPulse()

    if soundSfx1Queue & SFX1_CLAY_FLYING_TONE:
        startClayFlyingTone()

    if soundSfx1Queue & SFX1_DOG_LAUGH:
        startDogLaughTriangle()

    if soundSfx1Queue & SFX1_STOP_SQUARE2:
        stopPulse2OrClayFlyingTone()

    if soundSfx3Queue & SFX3_GROUND_THUD:
        startGroundThudPulsePair()

    if soundSfx3Queue & SFX3_CLAY_THROW:
        startClayThrowPulsePair()

    if soundSfx3Queue & SFX3_PERFECT_JINGLE:
        startFanfare(PERFECT_JINGLE)

    if soundSfx3Queue & SFX3_GAME_OVER_JINGLE:
        startFanfare(GAME_OVER_JINGLE)

    if soundSfx2Queue & SFX2_CLAY_START_THEME:
        startFanfare(CLAY_START_THEME)
    else if soundSfx2Queue & SFX2_GAME_OVER_THEME:
        startFanfare(GAME_OVER_THEME)
    else if soundSfx2Queue & SFX2_GOT_DUCK_JINGLE:
        startFanfare(GOT_DUCK_JINGLE)
    else if soundSfx2Queue & SFX2_DUCK_START_THEME:
        startFanfare(DUCK_START_THEME)
    else if soundSfx2Queue & SFX2_HIT_TABLE_SHUFFLE:
        startFanfare(HIT_TABLE_SHUFFLE)
    else if soundSfx2Queue & SFX2_BEAT_ROUND_THEME:
        startFanfare(BEAT_ROUND_THEME)

    clearConsumedQueueBits()
    stepActiveAudioEffectsOneFrame()

Important priority note

The original is not a full mixer with infinite simultaneous sounds. Several sounds share APU channels and can cut each other off. The most important practical priorities are:

1. Gunshot should always be audible immediately when a shot is accepted.
2. Bark/quack DMC samples can occur over other programmable-channel effects.
3. Fanfares can take over pulse/triangle/noise channels.
4. Clay flying tone uses pulse 2 and must be stopped when no clay is actively flying.
5. Dog laugh uses triangle and can be blocked by higher-priority fanfare behavior during game over.

Gameplay trigger map

Duck mode start

When loading the duck-game screen for GAME_A_ONE_DUCK or GAME_B_TWO_DUCKS:

queueSfx2(SFX2_DUCK_START_THEME)

Clay mode start

When loading clay shooting:

queueSfx2(SFX2_CLAY_START_THEME)

Shot accepted

When HandleZapperFunctions accepts a new trigger pull and decrements shotCount:

queueSfx1(SFX1_ZAPPER_SHOT)

This should happen before hit testing feedback resolves. It is tied to the shot, not to hit or miss.

Duck launch / flying

When a duck becomes FLYING_AND_SHOOTABLE:

- The entity does not need a unique launch sound.
- Once flying, every 8 frames while active, queue a wing-flap noise tick.
- The original also queues a quack when its internal quack cooldown reaches zero.

Implementation:

function updateDuckFlightAudio(duck):
    if duck.state != FLYING_AND_SHOOTABLE:
        return

    if frameCounter % 8 == 0:
        queueSfx1(SFX1_WING_FLAP)

    if duckQuackCooldown == 0:
        queueSfx3(SFX3_QUACK)
        duckQuackCooldown = 0x41       // normal cadence baseline
    else:
        duckQuackCooldown -= 1

Quack cooldown note

The original uses an internal value around $9F. While ducks are active, it counts down and queues quack when it reaches zero. A practical implementation can use a global duckQuackCooldown. Reset it to about 0x41 frames after a quack. If shotCount reaches zero, the original uses a shorter countdown branch around 0x15 in the duck entity handler, so escaped/fly-away behavior can quack more tightly.

Duck hit pause

When a duck is hit, it enters HIT_MARK_AND_SCORE, then HIT_PAUSE for 0x12 frames. During HIT_PAUSE, the original queues a quack around the middle of the pause, when the hit-pause timer reaches the equivalent of 0x0A.

Implementation:

onDuckHit(duck):
    duck.hitPauseTimer = 0x12
    duck.hasPlayedHitQuack = false

updateDuckHitPause(duck):
    duck.hitPauseTimer -= 1
    if duck.hitPauseTimer == 0x0A and not duck.hasPlayedHitQuack:
        queueSfx3(SFX3_QUACK)
        duck.hasPlayedHitQuack = true
    if duck.hitPauseTimer == 0:
        duck.state = START_FALLING

Duck starts falling

When state changes from START_FALLING into FALLING:

queueSfx1(SFX1_DUCK_FALL)

This happens when the score popup is spawned and the falling motion code is selected.

Duck hits ground

During FALLING, when duck.y >= 0xB0:

queueSfx3(SFX3_GROUND_THUD)
duck.state = CLEAR

Dog pre-duck bark

During the dog intro/walk/sniff animation before ducks are released, the dog barks on a repeating counter:

- initialize dogBarkCounter = 0x04 when entering the bark-capable dog state
- each frame decrement dogBarkCounter
- when it reaches 0, queue bark and reset to 0x10

Implementation:

function updateDogBarkAudio():
    dogBarkCounter -= 1
    if dogBarkCounter == 0:
        queueSfx3(SFX3_BARK)

Effect synthesis notes

Zapper shot

- Channel: noise
- Start on the exact frame the shot is accepted.
- Original noise effect has 0x30 table entries.
- The table advances once every 2 frames.
- Duration target: about 96 frames, or about 1.6 seconds, unless interrupted by a higher-priority event.
- Noise period descends through a sequence roughly like 0x0E, 0x0B, 0x05, then toward low values.
- Volume begins high and decays gradually.

Approximation:

startZapperShotNoise():
    activeZapperShot.index = 0
    activeZapperShot.subframe = 0
    noise.enabled = true
    noise.volume = 15

stepZapperShot():
    activeZapperShot.subframe += 1
    if activeZapperShot.subframe < 2:
        return
    activeZapperShot.subframe = 0
    i = activeZapperShot.index
    noise.period = ZAPPER_NOISE_PERIOD_TABLE[i]
    noise.volume = ZAPPER_VOLUME_TABLE[i]
    activeZapperShot.index += 1
    if activeZapperShot.index == 0x30:
        noise.enabled = false

Use these practical tables if you are synthesizing:

ZAPPER_NOISE_PERIOD_TABLE = [
  0x0E,0x0B,0x05,0x05,0x05,0x05,0x05,0x05,
  0x05,0x05,0x05,0x05,0x04,0x04,0x04,0x04,
  0x04,0x04,0x03,0x03,0x03,0x03,0x03,0x04,
  0x03,0x02,0x02,0x02,0x02,0x02,0x02,0x02,
  0x02,0x01,0x01,0x01,0x02,0x02,0x01,0x01,
  0x00,0x00,0x00,0x00,0x00,0x00,0x00,0x00
]

ZAPPER_VOLUME_TABLE = [
  0x0F,0x0F,0x0F,0x0F,0x0F,0x0F,0x0D,0x0C,
  0x08,0x08,0x08,0x07,0x07,0x07,0x06,0x06,
  0x04,0x04,0x04,0x04,0x04,0x04,0x04,0x04,
  0x03,0x03,0x03,0x03,0x03,0x03,0x03,0x03,
  0x02,0x02,0x02,0x02,0x02,0x02,0x02,0x02,
  0x02,0x02,0x02,0x02,0x02,0x02,0x02,0x02
]

These volume values are the lower four bits of the original noise-volume register bytes. If your audio layer accepts 0.0 to 1.0, divide by 15.

Wing flap

- Channel: noise
- Trigger cadence: every 8 gameplay frames while a duck is active and flying.
- Sound length target: short tick, about 4 frames.
- Original changes the noise period through a tiny 4-value sequence: 0, 2, 1, 0.

Approximation:

startWingFlapNoiseTick():
    wing.index = 0
    wing.active = true
    noise.enabled = true
    noise.volume = 3

stepWingFlap():
    noise.period = [0,2,1,0][wing.index]
    wing.index += 1
    if wing.index == 4:
        wing.active = false

Duck quack and dog bark

- Channel: DMC sample playback in the original.
- Bark sample address is loaded from the bark sample block.
- Quack sample address is loaded from the quack sample block.
- Both use DMC sample length register value 0x20.
- Bark uses DMC frequency index 0x0E.
- Quack uses DMC frequency index 0x0F.

Modern approximation:

- Use short licensed/recreated bark and quack samples.
- Keep bark and quack very dry, low bit-depth, and short.
- Bark should be lower and rougher than quack.
- Quack should be bright, clipped, and brief.
- These can layer over pulse/noise effects because they are DMC/sample-channel effects.

Dog laugh

- Channel: triangle.
- Trigger only when no ducks were hit in the duck wave.
- The original is a stepped triangle-channel pitch sequence with 14 pitch entries.
- It changes pitch at expanding frame thresholds: 6, 12, 18, and so on, ending around 84 frames, roughly 1.4 seconds at 60 fps.

Approximation:

DOG_LAUGH_TRIANGLE_PERIODS = [
  0x4F,0x53,0x58,0x5E,0x63,0x69,0x70,
  0x76,0x7E,0x85,0x8D,0x90,0x92,0x93
]

Use a stepped downward/laughing triangle tone. Each step should feel like the dog's laugh syllables, not a smooth slide.

Duck fall

- Channel: pulse 1.
- Trigger when the duck enters START_FALLING, at the same moment the score popup is spawned.
- Approximate as a short descending pulse tone.
- It should not wait until the duck hits the ground.

Ground thud

- Trigger when the falling duck reaches y >= 0xB0.
- Approximate as a very short low pulse/noise thump.
- This is separate from the duck-fall sound.

Clay throw

- Trigger on every individual clay launch.
- Approximate as a short two-pulse chirp or throw blip.
- It should trigger for both clays in the pair, including the second clay after its random release delay.

Clay flying tone

- Trigger about 5 frames after each clay launch.
- Uses pulse 2 in the original.
- It acts like the clay's moving-away/flying sound.
- Stop it when neither clay is actively flying.

Clay hit / shatter

- Channel: noise.
- Trigger on fragmentation frame 2.
- Approximate as a short noisy crack/shatter.

Fanfares and jingles

The original fanfare system uses note data for pulse 1, pulse 2, triangle, and sometimes noise. For a mechanics clone, these do not affect target behavior, but they do affect pacing because the game waits through several post-round timers while they play.

Required gameplay fanfares:

DUCK_START_THEME        // when duck game screen loads
CLAY_START_THEME        // when clay game screen loads
GOT_DUCK_JINGLE         // dog displays one or two hit ducks
HIT_TABLE_SHUFFLE       // during round-end hit-table shuffle
BEAT_ROUND_THEME        // pass line reached
PERFECT_JINGLE          // all 10 targets hit
GAME_OVER_JINGLE        // immediately after failing pass line
GAME_OVER_THEME         // game-over state

Modern implementation rule:

Even if you replace the exact melody with original audio of your own, keep the same trigger points and do not let these sounds change gameplay timers unless you intentionally model original post-round delays.

Audio acceptance checks

Duck modes:

- Pulling the trigger always plays the gunshot immediately, hit or miss.
- A flying duck produces wing-flap ticks every 8 frames.
- Quacks occur during active duck flight and once during hit pause.
- A shot duck plays duck-fall sound when it starts falling.
- A separate thud plays when y >= 0xB0.
- If no ducks in a wave are hit, dog laugh plays when the dog result animation begins.
- If at least one duck in a wave is hit, got-duck jingle plays when the dog result animation begins.
- The dog barks during the pre-duck dog animation on the 0x04 then 0x10-frame cadence.

Clay mode:

- Each clay launch plays clay throw.
- The second clay also plays clay throw after its own 1 to 64 frame launch delay.
- Clay flying tone starts about 5 frames after launch.
- Clay flying tone stops when no clay is actively flying.
- Clay hit/shatter noise plays on fragmentation frame 2, not immediately at trigger pull unless the hit transition and fragment frame happen in the same update.

Round flow:

- Hit-table shuffle sound is tied to the shuffle loop, not to target hits.
- Beat-round theme only plays if currentHitCount >= requiredHitCount.
- Perfect jingle only plays if currentHitCount == 10.
- Game-over jingle and game-over theme only play after the hit-table shuffle confirms currentHitCount < requiredHitCount.

Things to avoid for audio

Do not play wing flaps from animation frame changes unless the cadence is exactly every 8 frames.
Do not play duck fall and ground thud as one combined sound. They are separate events.
Do not play clay hit noise on the shot frame if the clay fragmentation frame has not reached 2 yet.
Do not let the clay flying tone continue after both clays are gone.
Do not treat bark and quack as ordinary noise-channel effects. They are sample-style DMC events in the original.
Do not use original ripped samples unless you have the rights. For development, use placeholders or synthesized replacements.

------------------------------------------------------------
14. ACCEPTANCE CHECKS
------------------------------------------------------------

Use these to check whether your implementation is close.

General

- Round always contains 10 targets.
- Game A has 1 duck per wave and 3 shots per duck.
- Game B has 2 ducks per wave and 3 shots total for the pair.
- Game C has 2 clays per wave and 3 shots total for the pair.
- The pass line is 6 hits through round 10, then 7, 8, 9, and finally 10 from round 20 onward.

Game A

- Round 1 ducks should feel slow and stay visible a long time, around 11.5 seconds total on average including launch and escape travel.
- Around round 8, average speed should feel roughly double round 1.
- Around round 12, average speed should feel roughly triple round 1.
- Around round 20, ducks should be visible roughly 5 seconds on average.
- Hitbox remains large through round 23, shrinks at round 24, then shrinks again from round 27 onward.
- Do not steer with controller input. This implementation is single player only.

Game B

- Two ducks launch with a stagger. First after about 48 frames, second after a random 1 to 64 frame delay.
- Ducks follow scripted paths, not bouncing free-flight behavior.
- Path completion speeds up because speed cycles consume more path substeps per frame.

Game C

- Two clays launch with a stagger. Pair start delay is about 128 frames, then second clay uses a random 1 to 64 frame delay.
- Clays shrink quickly as they move away.
- Clays are easier to hit when close because they use larger Zapper shapes, then shrink by distance and round bracket.
- Round 10+ clays should stay visible about 2.8 to 3.3 seconds depending on path.

------------------------------------------------------------
15. THINGS TO AVOID
------------------------------------------------------------

Do not implement ducks as physics bodies with random acceleration.
Do not use one smooth velocity vector per duck.
Do not give Game A and Game B the same flight behavior.
Do not implement second-player controller duck movement.
Do not make hitboxes equal to the visible sprite bounds.
Do not forget that Game B and Game C use 3 shots total for two targets.
Do not make the pass line increase every round. It uses the fixed table above.
Do not clamp clays visually by screen bounds. They clear by internal distance or vertical fixed-point state.
